# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Purpose

Personal vacation planning project for a family of 4 (2 adults + 2 teens, ages 17 and 15) for summer 2026. The **current itinerary is Bavaria + Salzburg + Vienna, July 11–22, 2026** (`itinerary.md`). Other destination options (Greece, St. Lucia) remain in the research files for reference.

## Key Files

- `itinerary_data.py` — **canonical day-plan source** for overview rows, timed events, transportation instructions, and daily notes
- `build_itineraries.py` — generates the synchronized schedule sections in both itinerary formats and rebuilds the printable daily handout
- `map_data.py` — canonical map definitions: locations, zoom, viewport, and generated asset names
- `build_maps.py` — downloads missing OSM tiles into `map_cache/` and renders finished graphics into `map_images/`
- `itinerary.md` — detailed working itinerary; its overview and daily-detail marker blocks are generated from `itinerary_data.py`, and its cost marker block is generated by `build_costs.py`
- `itinerary.html` — styled full-trip itinerary with the same generated schedule and cost marker blocks
- `daily_itinerary.html` — generated US-Letter handout with one printable sheet per day, times on the right, transportation details, and optional map-note space
- `bookings.md` — **canonical reservation record** for confirmed bookings and outstanding booking tasks
- `build_costs.py` — canonical cost data and generator for the itinerary cost sections and workbook
- `trip_costs.xlsx` — generated current-trip cost workbook; rebuild with `build_costs.py`
- `brochure_images/` — photos used in brochures (day-by-day filenames like `day4_neuschwanstein.jpg`)
- `archive/` — superseded plans, research, brochures, exports, and other reference material; do not actively maintain or harmonize these files unless a file is explicitly restored to the root

Keep the active root files harmonized: reservation records belong in `bookings.md`, matching day-plan details belong in `itinerary_data.py` followed by `build_itineraries.py`, and costs belong in `build_costs.py` followed by its generator run. Treat the archive as read-only historical context.

## Scripts

**Itinerary maps** (run whenever map locations or view settings change):
```bash
python3 build_maps.py
```
Reads `map_data.py`, reuses locally cached OpenStreetMap tiles from `map_cache/`, and writes finished, attributed PNG graphics to `map_images/`. Use `python3 build_maps.py --offline` to rebuild without network access. The daily handout references only these finished graphics; do not assemble map tiles in `build_itineraries.py`.

**Day plans and itinerary layouts** (run whenever daily schedule or transportation details change):
```bash
python3 build_itineraries.py
```
Reads `itinerary_data.py`, updates the generated overview and daily-detail blocks in `itinerary.md` and `itinerary.html`, and rewrites `daily_itinerary.html`. Never edit those generated marker blocks or the daily handout directly. Other sections of the detailed itinerary remain manually maintained.

**Cost estimate** (primary — run whenever costs change):
```bash
python build_costs.py
```
Reads the `COSTS` list in `build_costs.py`, writes `trip_costs.xlsx`, and injects a formatted cost table into both `itinerary.md` and `itinerary.html` between `<!-- COSTS_START -->` / `<!-- COSTS_END -->` sentinels. Edit costs only in `build_costs.py`; never edit the sentinel block directly. Requires `openpyxl`.

**Multi-destination spreadsheet** (legacy):
```bash
python build_vacation_spreadsheet.py
```
Legacy research generator for the archived `archive/vacation_research_2026.xlsx` multi-destination comparison. It is not part of the active itinerary synchronization workflow. Requires `openpyxl`.

## Brochure Workflow

Archived brochures are self-contained HTML files with inline CSS and `<img>` tags referencing `brochure_images/`. They are historical outputs and are not kept synchronized with the active itinerary.

## Booking Records Structure

`bookings.md` uses a consistent section layout per confirmed reservation:
- Header: vendor name + what was booked
- Sub-fields: booking/confirmation #, order #, date booked, travelers, date of service, contact info, cancellation policy, amount paid (with card/charge-as details)
- **"Still to Book" table** at the bottom tracks outstanding reservations with priority and notes.

When a new booking is confirmed, add a full entry at the top of the relevant section (Flights / Accommodation / Activities) and remove or update the corresponding row in the "Still to Book" table. Also update the matching cost item in `build_costs.py` (set `is_estimate=False` and update the amount), then re-run `python build_costs.py`.

## Conventions

- `*.BACKUP.md` files are gitignored; `*.BACKUP2.md` files are not — treat the non-ignored backups as reference snapshots, not the authoritative version.
- Loose JPEG files at the root (prefixed `preview_`, `check_`, or named by location) are working screenshots used during brochure development, not source assets.
- `_tmp_train_imgs.json` is a large scratch file from image search sessions — ignore it.
- The generated schedule blocks in `itinerary.md`, `itinerary.html`, and `daily_itinerary.html` must come from `itinerary_data.py`; do not make the same schedule edit independently in all three files.
